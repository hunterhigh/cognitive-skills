# Cognitive Skills 与 Project Craft：第一轮 Skill 体系迭代方案

## 方案范围

本轮迭代覆盖我们已经形成明确方向的八个 Skill：

1. `first-principles-dialogue`
2. `situational-analysis`
3. `strategic-analysis`
4. `communication-advisor`，候选改名为 `communication-advisor`
5. `project-framing`
6. `system-architecture`
7. `project-continuity`
8. `goal-discipline`

`project-foundation` 暂不进入本轮重构。它继续作为新长期软件项目的工程基础能力，只检查与其他 Skill 的接口和名称引用。原因不是它不重要，而是我们尚未对它形成新的用户校正；在缺乏证据时不为追求全套更新而修改。

本方案跨越 Cognitive Skills 与 Project Craft 两个独立仓库。概念设计可以共同进行，但修改、测试、提交和发布必须保持各自边界，不能用一个跨仓库提交制造伪统一。

## 体系目标

这轮迭代不建立主控 Skill，也不建立统一流水线。目标是让各 Skill 拥有清楚且不重复的工作对象，并能在真实任务中组合：

| Skill | 主要对象 | 期望状态变化 |
| --- | --- | --- |
| 第一性原理 | 原子事实、数理与逻辑关系、复杂命题 | 从原始材料与模糊认识形成可检验的事实—关系—命题结构 |
| 情境分析 | 问题的全面性 | 从局部成立的判断形成经过五层五维检查的情境判断 |
| 战略分析 | 优势的生成与转换 | 从当前局势形成能够创造、积累、保持和兑现优势的条件策略 |
| 沟通顾问 | 沟通情境与互动状态 | 从不知道如何理解、表达或推进，形成适合对象和关系的沟通行动 |
| 项目构思 | 项目方向与可行集 | 从模糊项目或功能方向形成目标、边界、候选路径和下一有效行动 |
| 系统架构 | 职责、依赖、状态与反馈结构 | 从关系混乱形成可工作、可观察、可维护和可演化的系统结构 |
| 项目连续性 | 项目层会议节奏 | 从零散项目交流形成能够反复进入、孕育想法并持续推进的会议节奏 |
| 目标纪律 | 当前工作范围与注意力 | 从大模型的完整性扩张收敛到直接服务用户当前任务的最小充分工作 |

这些状态转移共同服务“帮助用户持续进入更优可达状态”，但优势原则不成为一个新的中央组件。每个 Skill 只在自己的对象上解释什么是改善。

## 总体运行关系

### 项目之外

用户可以直接调用认知 Skill：

- 从材料和现实片段中重建认识：第一性原理；
- 检查问题是否看得足够全面：情境分析；
- 研究怎样获得并持续形成优势：战略分析；
- 处理具有明确目的的非亲密沟通：沟通顾问。

### 已存在项目之内

`project-continuity` 是项目层协作入口。它通过开会承接当前项目、形成讨论节奏、保存值得延续的想法和决定，并按当前议题使用认知或项目 Skill。它不是主控系统：专业判断仍由相应 Skill 完成，用户也可以直接要求某一能力。

项目会议中可能出现以下自然转移：

- 想法仍然是未经组织的现实碎片：使用第一性原理；
- 方案可能因遗漏现实关系而失败：使用情境分析；
- 问题变成怎样改变局势并建立长期优势：使用战略分析；
- 项目方向或首个切片不清楚：使用项目构思；
- 职责、状态、依赖和反馈成为决定性问题：使用系统架构；
- 需要与项目外其他人沟通：把该子问题交给沟通顾问；
- 讨论开始为了全面而扩张：由目标纪律静默收敛。

这不是必须依次通过的流程。会议可以直接进入实现，也可以停在更清楚的问题上。

## Skill 1：第一性原理

### 当前问题

现有 `first-principles-dialogue` 过于宏大，把认识论核心与 SMART 目标、商业目标、营销漏斗、预算、激励和其他应用混在同一个主文件中。它还从“先确定命题”进入，但用户的实际用法是从材料、现象和想法中提取原子事实与数理关系，再组合复杂命题。

### 目标本体

第一性原理应成为纯粹思考类 Skill：

`原始材料或现象 → 原子事实 → 数理/逻辑/因果/约束关系 → 候选复杂命题 → 检验与保留 → 新的事实结构`

它不预先规定必须证明哪个命题。用户提供的是探索方向，用于控制相关性，而不是限定结论。

六种现实透镜为命题生成提供以下约束：

- 系统：原子事实必须放回边界、关系、存量、流动和反馈中；
- 控制：提取能够观察状态、偏差、扰动和调节关系的信息；
- 博弈：把主体、信息、规则、行动和回应作为关系，而不是孤立事实；
- 进化：生成少量机制不同的候选命题，再由证据选择与保留；
- 热力学：限制无限拆解和无限命题生成的认知成本；
- 价值条件：允许同一事实在不同意义结构中形成不同规范命题，但不改变事实真值。

### 文件重构

- 主 `SKILL.md` 只保留事实提取、认识分类、关系提取、命题生成、检验和重组。
- 保留用户日常使用的事实清单、研究待办和研究执行模式。
- 删除 SMART、营销漏斗、商业目标和激励预算作为主文件能力。
- 数理关系留在核心，因为它属于关系表达；具体商业模型移出核心。
- 若应用内容仍有重复价值，放入按需参考；没有独立价值则删除，不为保留历史而保留。

### 行为验证

1. 给一组原始材料但不给中心命题，能否提取事实与关系并形成多个候选复杂命题。
2. 能否区分事实、假设、目标、设计选择、研究问题和指标代理。
3. 能否用关系和证据淘汰弱命题，而不是无限发散。
4. 用户要求固定事实清单或研究格式时，兼容性是否保留。
5. 普通商业词汇不再自动触发庞大的第一性原理工作流。

## Skill 2：情境分析

### 当前状态

候选版本已经改名为 `situational-analysis`，主文件已重新以五层五维为核心。当前不是继续增加概念，而是验证它是否真的提高问题全面性。

### 核心不变量

- 五层纵向深化：信息、逻辑、系统、人性、意义；
- 五维横向扩展：时间、利益、治略、博弈、哲理；
- 不输出固定二十五格；
- 只展开会改变结论、取舍或行动的关系；
- 最终从全面观察收敛到判断，不停在“事情很复杂”。

### 下一轮工作

- 用真实问题验证每层、每维的解释是否符合用户原始理解。
- 检查“治略”和“哲理”是否因模型常识而被稀释或误译。
- 精简重复的证据、决策和系统表述，确保五层五维始终是主线。
- 增加跨层跨维案例，但只保留真正改变判断的交叉关系。

### 行为验证

1. 局部技术方案是否被放回实际使用、维护、利益和治理关系。
2. 用户亲历体验是否被承认为体验事实，同时避免未经验证的因果归因。
3. 简单窄任务是否不会被强行扩展。
4. 复杂问题是否能指出决定性遗漏，而不是平均覆盖所有维度。
5. 与战略分析同时调用时，是否共享事实且分工清楚。

## Skill 3：战略分析

### 当前状态

`strategic-analysis` 已形成候选实现，并围绕六种现实透镜增加战略场、优势机制、策略定义与失败诊断。下一步重点是验证“优势”与“策略”的时间结构，而不是继续增加理论。

### 核心不变量

策略定义为：在相关时间范围内，根据状态、反馈和他方回应选择并组织行动，以创造、积累、保持或兑现优势条件的连贯政策。

优势至少区分：

- 即时优势；
- 位置优势；
- 动态优势；
- 终局优势。

一个战略动作可以不立即兑现收益，但必须说明它建立什么条件、怎样转换、何时验证和何时停止。“长期布局”不能成为不可证伪的解释。

### 下一轮工作

- 用非商业场景检验优势机制是否仍成立，避免 Skill 退化成商业战略顾问。
- 检查策略是否包含状态条件和回应分支，而不只是长期计划。
- 检查九种优势机制是否存在重复，可否进一步压缩。
- 用合作场景验证“优势”不会被默认翻译成战胜他人。
- 与情境分析共同使用，验证前者提供全面性、后者提供轨迹设计。

### 行为验证

1. 没有即时收益的布局能否被合理评价。
2. 能否说明位置优势向终局结果的转换机制。
3. 能否识别漂亮位置却无法兑现的策略。
4. 能否预判他方回应而不猜测动机。
5. 能否在简单问题中拒绝生成宏大战略。

## Skill 4：通用沟通顾问

### 当前问题

现有 `communication-advisor` 把能力限定在领导、同事、客户和合作方。它的真实本体更接近“沟通情境中的顾问”：帮助用户理解互动、决定是否以及怎样沟通、形成表达，并根据回应继续调整。

### 范围边界

扩展后覆盖具有明确目的和现实结果的沟通，例如工作协作、商业沟通、服务交涉、谈判、公开表达、陌生人或一般社会互动。

明确不覆盖亲密关系、家庭和朋友关系咨询。原因不是这些沟通不重要，而是其依恋、情感历史和关系伦理具有不同本体，不能由工作与目标沟通能力顺便吞并。

### 候选命名

将 `communication-advisor` 改名为 `communication-advisor`。名称直接表达它是沟通咨询入口；工作对齐成为按需加载的高频模式。

### 目标结构

1. 理解沟通情境：对象、关系、事实、目的、渠道、时机和后果；
2. 判断沟通任务：理解、表达、询问、请求、拒绝、说服、协商、澄清、修复或升级；
3. 设计动作：是否沟通、先和谁沟通、用什么方式、希望改变什么状态；
4. 形成自然表达：消息、谈话结构或回应；
5. 根据真实回应更新判断，而不预写无限话术树。

### 文件重构

- 主文件改为通用沟通判断与行动。
- 现有工作责任、资源请求、风险升级、交接和多方局面移入工作沟通参考。
- 保留“默认善意但不天真”“结论直接、关系柔和”“事实支持到哪里判断到哪里”。
- 新增排除边界，防止自动进入心理治疗、亲密关系判断或人格诊断。

### 行为验证

1. 一句普通消息能否直接改好，不展示完整咨询框架。
2. 工作沟通能力是否保持，不因通用化而变浅。
3. 非工作但目标明确的沟通能否正确进入。
4. 亲密关系与家庭咨询能否明确不误触发。
5. 沟通顾问与战略分析同时出现时，前者负责互动行动，后者负责局势轨迹。

## Skill 5：项目构思

### 当前判断

`project-framing` 的本体基本成立：把模糊项目或功能方向变成目标、边界、实质候选路径和下一有效行动。用户认可当前优化方向，不需要大规模重写。

### 迭代重点

- 区分“列出更多方案”与“扩大真实可行集”。候选方向必须在资源、权限和时机上可能成立。
- 明确下一动作是在兑现价值还是购买决策信息。
- 原型只有在能区分关键假设时才是合理下一步，不因可逆就默认原型。
- 当主要问题从“做什么”变成“各部分怎样连接”，交给系统架构。
- 已存在项目中的构思可由项目连续性会议触发；新项目尚未存在时可以直接调用项目构思。

### 行为验证

1. 模糊项目能否形成少数实质不同的方向。
2. 已经清楚的需求能否快速退出而不重复 framing。
3. 是否过早进入架构或实施计划。
4. 下一动作能否明确减少哪个未知或产生什么价值。

## Skill 6：系统架构

### 当前判断

`system-architecture` 已拥有关系、边界、信息、状态、执行、资源、运行和演进的完整本体。用户认可增加维护、可观察、恢复与退役判断。

### 迭代重点

每项重要结构选择应能够说明：

- 它扩大什么能力或可行域；
- 引入什么长期维护、理解和协调成本；
- 失败如何被观察；
- 怎样恢复、替换或隔离；
- 什么条件要求重审或退役。

这些是判断要求，不是强制文档。普通局部修改不得自动升级成完整架构流程。

### 边界

- 情境分析判断结构方案在现实中是否全面成立；
- 战略分析判断结构变化能否形成有利轨迹；
- 系统架构拥有组件职责、接口、状态与运行关系的设计；
- 项目基础拥有新项目工程文件生成与确定性验证。

### 行为验证

1. 新系统设计是否同时考虑工作、状态、反馈和维护。
2. 既有系统演进是否区分实际结构、试验结构和候选结构。
3. AI 指令、模型能力和运行环境保证是否被正确区分。
4. 简单修改是否保持比例。

## Skill 7：项目连续性

### 当前问题

现有 `project-continuity` 偏重上下文恢复、工作项和记录。用户的高频真实用途是通过和 Codex 开会建立工作节奏，在会议中产生想法、讨论、修正、形成决定并继续推进项目。

### 目标本体

`零散项目交流 → 可以反复进入、持续孕育想法并推动工作的项目会议节奏`

它必须在项目已经存在时运行，始终是项目层工作 Skill。没有项目的一次性思考或新想法不因“想讨论”就触发 continuity；新项目方向可以先进入 `project-framing`，项目形成后再建立连续性。

### 会议能力

- 承接当前项目、最近议题和用户新的 concern；
- 允许没有成熟结论的想法在会议中形成；
- 一次推进当前最重要的问题，而非每轮重写全案；
- 按议题使用第一性原理、情境分析、战略分析或项目能力；
- 从讨论自然转入研究、实验、实现、复盘或暂存；
- 保存值得下次继续的决定、开放问题、停点与反馈；
- 让用户无需管理工作项、线程和内部路由。

### 非主控边界

项目连续性是会议空间与节奏载体，不是系统级主控。它不定义其他 Skill 的真理、不替专业能力作判断，也不要求所有项目动作从它进入。明确任务可以直接调用专业 Skill；会议中专业对象形成后，相应 Skill 拥有判断。

### 文件重构

- 主文件从“接续—推进—记录”重排为“进入会议—共同思考—转入行动—保持节奏”。
- 恢复、工作项和记录降为维持会议节奏的支持机制。
- 明确只在项目存在时触发。
- 增加想法尚未成形但属于既有项目的场景。
- 保留对外人类沟通子问题与沟通顾问的边界。

### 行为验证

1. 用户说“开会讨论这个项目”时，能否直接进入有内容的讨论，而非索要固定议程。
2. 新想法能否在会议中逐渐形成，而不是被迫立即变成任务。
3. 讨论、实现和复盘之间能否自然切换。
4. 项目外普通问答是否不误触发。
5. 恢复项目时是否保留节奏，而不倾倒全部历史记录。

## Skill 8：目标纪律

### 当前问题

`goal-discipline` 本来已经很短，但第二章曾试图加入状态贡献、可行性、选择权和优势评价，这会使它长成另一个分析 Skill，违背用户对它的定位。

### 目标本体

它是一个静默、全局、最小的收敛原则，用来对抗大模型为了完整性而胡乱命中各种情况、增加框架和扩大工作。

只保留五个判断：

1. 用户当前真正要完成什么；
2. 用户明确要求的深度、过程和交付物是什么；
3. 当前步骤是否直接服务任务或解除必要阻塞；
4. 是否正在为了完整、专业感或可见工作量增加无关内容；
5. 当前任务是否已经完成，应该停止。

它不生成额外输出，不评价人生目标，不复制情境与战略分析，也不以“最小”取消用户明确要求的长文、研究、实验或创作。

### 文件重构

- 将主文件压缩到最小充分指令。
- 删除可能诱发额外分析的宽泛贡献分类。
- 保留“用户明确要求的过程与深度属于目标”的关键保护。
- 加入“完整性冲动不是工作授权”的直接约束。

### 行为验证

1. 明确机械任务是否直接完成。
2. 用户要求长文时是否不会错误压缩。
3. 研究是否在新增信息不再改变交付时停止。
4. 是否减少不必要的文档、备选、测试、代理和架构。
5. 是否完全不向用户展示自己的检查过程。

## 实施顺序

### 阶段 0：建立基线

先保存每个 Skill 的典型案例、邻接边界案例和反例。记录旧版在取证、判断、行动、篇幅、误触发和停止方面的表现。没有基线，就无法判断“更完整”是否真的更好。

### 阶段 1：完成 Cognitive Skills 核心

1. 重构第一性原理，这是当前本体偏差与上下文成本最大的一项。
2. 验证已经重构的情境分析。
3. 验证新建的战略分析及其与情境分析的组合。
4. 将工作对齐升级为通用沟通顾问，并完成排除边界测试。

每个 Skill 单独形成可识别变更和行为证据，不用一次大提交合并所有原因。

### 阶段 2：重构 Project Craft 的运行入口

1. 先重构 `project-continuity`，把会议节奏恢复为核心。
2. 再压缩 `goal-discipline`，使其成为真正的最小全局约束。

二者会影响高频日常协作，应先用真实项目会议试用，再修改项目构思和架构。

### 阶段 3：局部增强项目能力

1. 给 `project-framing` 增加真实可行集、信息价值和向架构退出的边界。
2. 给 `system-architecture` 增加维护、观察、恢复和退役判断。
3. 只检查 `project-foundation` 的接口，不修改其本体。

### 阶段 4：组合验证

至少验证以下组合：

- 第一性原理 + 情境分析：事实和命题生成是否仍会被现实关系校正；
- 情境分析 + 战略分析：全面性与优势轨迹是否互补而不重复；
- 项目连续性 + 第一性原理：会议中的原始想法能否形成认识结构；
- 项目连续性 + 项目构思：既有项目中的新方向能否形成可行动切片；
- 战略分析 + 系统架构：优势机制能否落实为结构，同时不侵占架构判断；
- 项目连续性 + 沟通顾问：项目会议中的对外沟通能否作为子问题处理；
- 目标纪律 + 任意组合：是否减少无关扩张而不降低用户要求的深度。

## 版本与验证原则

- 格式验证只证明 Skill 可以加载，不证明行为改善。
- 同一案例需要比较旧版、新版和无 Skill 的表现。
- 评价状态变化、遗漏、取舍、行动与停止，不检查是否复述框架术语。
- 对模型波动较大的结论进行重复测试，不从一次成功推断稳定能力。
- 一次只修改能够被独立解释的机制；无差异或变差的修改应撤回。
- Skill 变长需要证明新增上下文改变了行为；否则优先删除或移入按需参考。
- 用户实际使用反馈高于设计者对“理论完整”的偏好。

## 第一轮完成条件

本轮迭代在以下条件同时满足时结束：

1. 八个 Skill 均有清楚、互不重复的主要对象和状态转移；
2. 第一性原理不再包含 SMART、漏斗等应用性膨胀；
3. 情境分析稳定以五层五维提供问题全面性；
4. 战略分析能解释优势跨时间生成与兑现；
5. 沟通顾问完成通用化且不误入亲密关系咨询；
6. 项目连续性能够通过开会建立用户认可的工作节奏；
7. 目标纪律保持最小、静默并能有效抑制完整性扩张；
8. 项目构思和系统架构的局部增强通过边界案例；
9. 关键组合没有明显重复、互相覆盖或上下文爆炸；
10. 两个仓库分别完成自身验证，未建立新的中央主控或跨仓库运行依赖。

达到这些条件后停止第一轮，不自动继续创建新 Skill、统一协议或评价平台。后续演化由真实使用中的重复失败、用户反馈和可复现案例触发。
