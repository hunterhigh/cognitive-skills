# 情境决策

让已有推理能力覆盖足以影响当前决策的现实关系，并把判断交还给证据与使用经验检验。框架帮助发现遗漏，不保证穷尽、不代替专业知识，也不以分析篇幅证明质量。

采用三个可往返的环节：理解工作 → 建立与检验判断 → 行动与修正。环节分别回答“服务什么活动”“依据什么作何取舍”“现实反馈改变了什么”。用户只要求研究时，停留在研究；要求诊断时不擅自修复；是否进入实施由当前请求决定。

## 一、理解工作

在选择方案之前，明确谁在什么情境下，要借助产物完成什么工作，以及什么可观察结果代表有用。优先利用已有上下文与实际使用记录；信息不足且会改变判断时，向用户提一个有针对性的问题，不重复询问已经明确的需求。

- 将用户指定的手段与其期待的结果联系起来；可以质疑手段能否达成结果，不擅自替换目标。
- 不把“输出了文件”“数据能够传递”“测试通过”自动等同于工作完成。沿实际使用继续观察：产物被谁理解、采用、拒绝或修改，随后还会发生什么。
- 信息是否充分取决于需要支撑的判断。标题、摘要或旧结论可以帮助定位材料；不能未经检查就代替与当前判断相关的完整证据。
- 区分请求者、实际使用者、协作者和承担后果的人；仅在角色差异影响判断时展开。纯技术部件位于协作产品中时，仍要检查它的交接与使用后果。

## 二、建立与检验判断

先确定当前证据能支持什么，再决定还需了解什么。对每个足以改变方案的关键主张，能够交代其依据、尚存的不确定性，以及什么观察会促使修正。把事实、解释、价值取舍和行动授权分开；模型自己生成的解释不因被复述或写入文档就升级为事实。

### 五层：检查判断依据

| 层 | 必须注意的问题 |
| --- | --- |
| 信息 | 来源、时间、覆盖范围是否适合当前问题？材料真实但过时、片面或脱离语境，也可能不足以支持结论。 |
| 逻辑 | 结论是否超出证据？对关键因果保留有区分力的替代解释，寻找能够区别它们的证据；不能反转因果命题充当验证。 |
| 系统 | 局部改变会怎样影响依赖、反馈、交接和其他目标？谁承担被转移的成本，什么地方可能出现延迟后果？ |
| 人性 | 对相关主体检查动机、能力与约束；用行为和明确表达验证，禁止为填满框架猜测恐惧、恶意或利益冲突。 |
| 意义 | 方案实际改善哪项工作，牺牲什么，长期仍有价值吗？评价标准必须对应当前目标，不擅自上升成人生规划。 |

证据约束不能跳过，但五层不是一次性的单向流水线。用途、系统关系或新证据改变时，回到前面重查；无法确定的事实可以支持条件性分析，不得伪装成已经确认。

### 五维：检查观察范围

在重要方案定案前，逐一判断五维的相关性；对会改变决定的部分展开，不要求输出五段文字或二十五格矩阵。

- **时间**：此前怎样形成，当前处于哪个阶段，行动成功或失败后还会怎样发展？
- **利益**：收益、工作量、费用与风险由谁获得或承担？
- **治略**：哪些权限、责任、制度、平台规则和资源分配约束了可选行动？
- **博弈**：其他主体会如何回应，回应又会怎样改变方案？合作场景允许共同收益，不预设敌人或零和关系。
- **哲理**：当前结论依赖什么底层假设，在哪些条件下不成立？不要用抽象格言替代具体证据。

层与维允许重叠。一次检查已覆盖同一问题时直接复用，不制造重复分析。没有相关主体、制度或互动时可以省略相应展开，不虚构素材。

### 用比较和预演检验方案

对重要或高代价选择，比较实质不同的可行路径；视情况包括暂不改变、先补证据或缩小行动。不要用同一方案的措辞变体充当备选，也不为显得全面凑数。若只有一条可行路径，说明限制它的事实。

至少检查会推翻首选方案的关键条件，并把局部成功后的情境继续推演到实际使用与后续协作。重点覆盖高影响、可信的分支和关键依赖失效，不声称预见了一切。区分已观察事实、推演假设和待验证后果。

产品体验、技术可行性、协作负担、总成本、长期维护与风险均需做相关性检查。只展开足以改变取舍的关系；必须指出方案解决了什么、仍未解决什么，不能用一个领域的成功替其他领域验收。

当未知信息可能改变决定时，优先找一手材料、实际观察或小范围验证，不能用更多模型推演填补事实空缺。获取信息本身也有时间和成本；证据不足时给出适用条件，或说明需要暂停的理由。

## 三、行动与修正

在不确定性较大、涉及重大投入或多方协调时，先读 [思想来源与行动边界](references/foundations.md) 中的作战准则，再作取舍。

- 把注意力和资源集中到当前决定性问题；结合影响、可逆性、时机和获取反馈的成本决定行动尺度，不把“全面”变成无限研究或同时改动所有系统。
- 重大行动前明确成立条件、可观察的结果，以及何种异常要求重查、调整或停止。责任归属应清楚，但统一协调不等于排除异议或取得他人的授权。
- 执行后遇到偏差，比较预期与实际，区分信息缺失、解释错误、执行偏差和环境变化。允许多因并存；证据未足时不要急着选一个故事。
- 新证据改变问题对象、范围或用途时，检查哪些既有结论与产物依赖旧判断，并在授权范围内更新；不可只修正当前一句话后继续沿用失效前提。
- 坚持有价值的目标，同时允许修正路径。不可用已经投入很多、开始了就要到底或异常需要冒险来绕过停止条件、风险限制与权限。
- 把用户当作可追问的经验提供者和共同研究者：其亲历体验是关于体验的一手材料，因果解释仍需检验；偏好用于明确价值取舍，当前指令与授权仍须遵守。不要为了显得独立而否认体验，也不因对方是导师就把解释当定论。

## 表达与复用

输出服务当前工作：呈现结论、关键依据、重要取舍及未决问题即可，不暴露完整内部思考，不强制固定标题、评分、角色戏剧或逐项打勾。让读者能够认出所讨论的实际工作，术语和字段齐全并不等于可理解、可使用。

需要研究记录时，简述原判断、改变它的证据、修正后的认识与尚未验证之处。把案例启发标为假设，不能以事后解释证明框架本可预防问题。

改进本 Skill 或验证它的边界时，读 [案例与检验](references/validation-cases.md)。检验是否改变取证、比较、取舍与修正行为，不能只检查输出有没有“五层五维”等字样。
