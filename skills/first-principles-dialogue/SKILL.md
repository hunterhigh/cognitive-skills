# 第一性原理对话

从现实材料中重建能够被检验的认识结构。复杂命题是原子事实与关系组合后的产物，不是必须预先确定的入口。

用户可以提供一个现象、材料、困惑、想法或探索方向。探索方向只用于判断相关性，不能预先限定必须证明的结论。

## 1. 提取认识原子

先尽量还原材料中能够独立判断真假的最小陈述，并区分：

- **原子事实**：直接观察、已经确认或定义层面的陈述；
- **公理／原则**：本次推理接受的逻辑、数学、物理或规范前提；
- **假设**：为了继续推理暂时采用、以后可以检验的命题；
- **目标／偏好**：用户希望发生的结果，不是关于世界的事实；
- **设计选择**：可以由用户或系统改变的机制；
- **研究问题**：真值尚未知、需要证据的命题；
- **指标代理**：用来近似不可直接观察对象的测量；
- **定义**：本次讨论中概念的使用边界。

把事实与解释、原因与相关、描述与评价、必要与充分条件分开。用户纠正分类时，显式更新认识结构，不维护模型原先的漂亮解释。

原子化是一种受控近似。现实中的事实可能相互依赖、边界会随用途改变；不要假装所有原子永远独立，也不能因无法完美拆分就放弃精确表达。

## 2. 提取关系

事实只有进入关系才形成解释能力。根据材料提取会改变命题的关系：

- 逻辑：与、或、非、蕴含、必要、充分、互斥和条件；
- 数学：变量、函数、比例、约束、阈值、概率、向量、矩阵与目标函数；
- 因果：候选机制、中介、混杂、反馈和反事实；
- 时间：先后、延迟、积累、衰减、阶段和失效条件；
- 系统：边界、存量、流动、依赖、反馈和涌现；
- 主体：信息、行动、规则、利益、承诺和相互回应；
- 选择：变异、筛选、保留、路径依赖和环境适配；
- 资源：时间、能量、注意力、资金、能力和维护投入。

优先把能够表达为数值或关系式的内容明确写出，但不制造虚假精度。数值未知时保留变量，并说明它怎样影响结论。

## 3. 组合候选复杂命题

从原子和关系中生成少量机制上真正不同的复杂命题。不要只把用户原句换一种措辞，也不要无限生成所有逻辑可能。

每个候选命题应说明：

- 它由哪些原子事实、公理、假设和关系组成；
- 哪些条件成立时命题成立；
- 它能解释什么，不能解释什么；
- 它与其他候选命题的决定性差异；
- 什么观察能够证实、削弱或推翻它；
- 若成立，它会改变什么认识或行动。

候选数量由材料中的机制差异决定。只有一个合理结构时不凑数；存在多种因果或系统解释时，不因首个故事连贯就停止。

## 4. 检验与排除

为每个关键子命题指定证据路径：

- 从定义、公理或已接受前提演绎；
- 从重复观察、案例、数据或实验归纳；
- 由用户或材料中的直接经验确认；
- 依赖稳定的数学、逻辑或物理关系；
- 需要外部一手资料或新实验验证。

检查反例、边界和极端状态。在适用时测试零值、最大值、资源受限、饱和、对抗、时间延迟和环境改变。候选很多时先确定排除标准，再枚举和淘汰。

不要把数字表达能力当作真理。公式能澄清关系，但系数、代理、边界和因果仍需证据。

## 5. 保留、重组与继续探索

把候选命题判断为成立、初步成立、待验证、不成立或无法判断。只把证据足够的原子、关系和命题纳入当前事实结构。

完成时说明：

- 当前能够稳定保留的事实与关系；
- 哪些复杂命题成立到什么程度；
- 哪些命题被排除以及原因；
- 最小的下一证据是什么；
- 新认识对用户的探索方向产生什么影响。

结论可以是一个新的问题结构，而不必强行给行动建议。需要判断现实情境是否全面时使用 `situational-analysis`；需要研究怎样改变局势并获得优势时使用 `strategic-analysis`。

## 六种现实透镜的使用

六种透镜帮助发现关系，而不是成为六段固定输出：

- 系统提醒原子事实仍处在边界、流动与反馈中；
- 控制提醒观察状态、偏差、扰动和调节关系；
- 博弈提醒其他主体会根据规则和信息回应；
- 进化提醒生成候选、选择和保留，避免过早锁定单一命题；
- 热力学提醒拆解、研究和维持秩序都有成本；
- 价值条件提醒规范命题可能依赖生活条件和意义结构，但不能改变事实真值。

只使用会改变当前命题结构的透镜。

## 输出模式

普通对话根据用户需要自然表达，不强制固定模板。

- 用户要求事实清单时，读取 [事实清单模式](references/fact-list.md)。
- 用户要求研究待办或执行命题研究时，读取 [研究模式](references/research-workflow.md)。
- 改进或验证本 Skill 时，读取 [验证用例](references/validation-cases.md)。

## 边界

- 不把目标、设计选择、研究问题或代理指标伪装成事实或假设。
- 不从用户探索方向倒推出一个必须成立的中心命题。
- 不因发现更多细节就无限拆分；新增原子或命题必须提高解释、检验或判断能力。
- 不把第一性原理等同于“从零忽略已有知识”；可靠经验与一手研究仍是证据。
- 不复制 SMART、商业目标、营销漏斗、预算和激励等应用框架；它们需要时由相应领域能力承担。
